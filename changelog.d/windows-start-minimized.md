kind: lane windows start minimized (`LANE_START_WINDOW=normal` undoes it)
---
CireSnave 2026-11-19: *"I don't need to see every lane start. Is it possible to have their windows start minimized?"* `lane-restart`'s `wt.exe` launch now opens the lane's window with the fixed title `lane-<role>` (`--title ... --suppressApplicationTitle`), then finds it by class `CASCADIA_HOSTING_WINDOW_CLASS` and that exact title and calls `ShowWindow(SW_MINIMIZE)` every 250 ms until it stays minimized (at most 5 s, never a reason to fail a launch; the outcome goes to `spawn.log`). **The window is visible for about 0.5-1 s first; that is how it works, not a bug.** `LANE_START_WINDOW=normal` restores the old launch (no title, no minimize). New module `window_start`, `windows-sys` feature `Win32_UI_WindowsAndMessaging`. **Measured 2026-11-20** (scratch launches, interleaved with an untouched control): title + retried `SW_MINIMIZE` left 10/10 windows iconic at 1, 2 and 4 s, control 0/10; through the real `spawn_launch` and `lane-restart host` with a benign child, 5/5 iconic at 1, 2 and 4 s and the hosted child ran 10/10 (5 minimized, 5 normal), windows minimized 720-740 ms after the launch. **What did not work** (so not used): the start state of the process running `wt.exe` (`Start-Process -WindowStyle Minimized` 1/3 then 0/2, `CreateProcessW` `wShowWindow` 7 and 2 and `start /min` 0/1 each); a single `SW_SHOWMINNOACTIVE` 0/5; a single `SW_MINIMIZE` at first sight 0/10. **Not measured:** a real `lane-restart start` of a lane (it is PM-only; the test used the same `spawn_launch` and `host` with a stand-in child), input delivered to a minimized host, and agentlife's own `src/launch.rs` launcher (`wt -w agentlife-<k> new-tab`), which is unchanged.
