CireSnave 2026-11-19: *"I don't need to see every lane start. Is it possible to have their windows start minimized?"* `lane-restart`'s `wt.exe` launch now opens the lane's window with the fixed title `lane-<role>` (`--title ... --suppressApplicationTitle`), then finds it by class `CASCADIA_HOSTING_WINDOW_CLASS` and that exact title and calls `ShowWindow(SW_MINIMIZE)` every 250 ms until it stays minimized (at most 5 s, never a reason to fail a launch; the outcome goes to `spawn.log`). **The window is visible for about 0.5-1 s first; that is how it works, not a bug.** `LANE_START_WINDOW=normal` restores the old launch (no title, no minimize). New module `window_start`, `windows-sys` feature `Win32_UI_WindowsAndMessaging`. **Measured 2026-11-20** (scratch launches, interleaved with an untouched control): title + retried `SW_MINIMIZE` left 10/10 windows iconic at 1, 2 and 4 s, control 0/10; through the real `spawn_launch` and `lane-restart host` with a benign child, 5/5 iconic at 1, 2 and 4 s and the hosted child ran 10/10 (5 minimized, 5 normal), windows minimized 720-740 ms after the launch. **What did not work** (so not used): the start state of the process running `wt.exe` (`Start-Process -WindowStyle Minimized` 1/3 then 0/2, `CreateProcessW` `wShowWindow` 7 and 2 and `start /min` 0/1 each); a single `SW_SHOWMINNOACTIVE` 0/5; a single `SW_MINIMIZE` at first sight 0/10. **Real starts (2026-11-20, the PM ran `lane-restart start` on the scratch lane `launchtest` with this build, N=2):** both logged `window minimized after 740 ms (2 calls)` in `spawn.log` and both reached launch-to-live in 4 s; the `lane-launchtest` window was iconic when I read it (late: 42 s and 4.7 min after, not at 1/2/4 s); in start 1 the host relayed 1.9 MB of lane output while minimized, and both startup dialogs were answered by the host's handlers while minimized. Start 2's session then sat idle because the lane declined a PM self-stop `[TASK]` as untrusted (read from its host log: not a dialog, not blocked input, not caused by minimizing; start 1 acted on the same kind of message). Real-start control (`LANE_START_WINDOW=normal`): **0 run**, the test was ended at N=2. **Not measured:** keystrokes typed by a person into a minimized window, any real start read at 1/2/4 s, and agentlife's own `src/launch.rs` launcher (`wt -w agentlife-<k> new-tab`), which is unchanged. **Lane-run only (not repeated by the PM or CI):** the scratch and stand-in measurements above. **Also in this PR:** `scripts/gpu-run-native-test.sh` accepts the ps1's own version in the interleave log check (baracuda's ps1 is v4, the native is v3; run 14/14 with the real ps1 while the lock was free); ROADMAP O3 closed (two pwsh seen, one a live lane's shell, nothing killed); ERR-012: the 13 functions are `#[must_use]` and the 50 discarded calls are written `let _ =`.
