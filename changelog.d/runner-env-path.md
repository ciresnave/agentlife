kind: `gh-runner-setup.ps1`: runner `.env` puts Git bash before the WSL launcher and gives jobs Rust; probe as the account
---
The first mlmf job (2026-11-12) died before any test: `shell: bash` resolved to `C:\Windows\System32\bash.exe` (the WSL launcher, no distribution installed) and `dtolnay/rust-toolchain` failed the same way. `<runner dir>\.env` now carries `PATH` (Git `bin` and `usr\bin` first, then `C:\rust\.cargo\bin`, then the machine PATH without repeats), `RUSTUP_HOME=C:\rust\.rustup` (the shared toolchains) and `CARGO_HOME=<Root>\cargo-home` (the account's own cache, so a job cannot write into the shared `.cargo`); `-GitRoot` and `-RustRoot` override the defaults and `-RustRoot ''` leaves Rust out. After the service read-back the script runs a probe AS the account (`Start-Process -Credential`, Secondary Logon, with the `.env` values): bash must resolve under Git's root, `bash -c "echo ok"` must print `ok`, and `cargo`/`rustc --version` must run; any failure stops the run with the probe's output. With `-Rearm` (#272) the one existing command fixes an installed runner. Verified by `gh-runner-setup-env.tests.ps1` (pure functions, plus the generated environment run under a real process as the current user: Git's bash first, bash, cargo and rustc run; dropping the Git-first entries turns 5 checks red). NOT measured: the probe running as a `ghr-*` account (needs an elevated run), and that the runner's Listener applies a `PATH` from `.env` (it applies `PSExecutionPolicyPreference` from it, measured 2026-10-17).
