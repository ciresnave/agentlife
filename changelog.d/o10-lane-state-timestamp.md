kind: **BREAKING**: lane-state's `LaneState::updated_at` and `SystemFacts::now` are `lane_state::timestamp::Timestamp`, not `chrono::DateTime<Utc>`
---
O10 (RUSTSEC-2026-0543, chrono is unmaintained), lane-state stage. New `lane_state::timestamp::Timestamp`, a newtype over `jiff::Timestamp` that serialises as RFC 3339, so every state file already on disk reads back unchanged (`an_existing_state_file_reads_back_and_rewrites_with_the_same_instant`: `Z`, nanosecond and `+02:00` forms). lane-state no longer depends on chrono. Migration for a consumer: `Timestamp::now()`, `from_unix_secs`, `unix_secs`, `secs_since`, `plus_secs`, `to_rfc3339`. lane-restart and the root crate still use chrono for their own values and convert at the lane-state boundary (`ts_compat`); they leave chrono in their own stages. Verified by the workspace tests, clippy (Windows and the Linux target) and mutations: a flipped age sign in `authorize` fails `the_age_of_a_state_file_is_judged_against_the_facts_own_clock_in_the_right_direction` (the two existing stale/future tests did not catch it, so that test is new). Not run on a real lane.
